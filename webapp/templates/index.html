🛡️ Credit Card Fraud Detection Platform

Classify new transactions as Fraud / Legitimate through an embedded LightGBM model (trained on 284,807 transactions — PR-AUC = 0.880) — no retraining needed.

Model: LightGBM (SMOTE) PR-AUC 0.880 ROC-AUC 0.982

❓ Why do the column names look strange?

The dataset was anonymized by the issuing bank: the columns V1–V28 are not real-world features. They are Principal Components (a dimensionality-reduction transform) of 28 original, confidential card-usage features. The originals were withheld for confidentiality, so no public real-world name exists for them — the model learns fraud patterns directly from these components.

  • Time = seconds elapsed since the first transaction (two consecutive days are covered).
  • Amount = the transaction amount in the original currency.
  • Class = the label (1 = fraud, 0 = legitimate), used for training/evaluation only — never a model input.
  • Uploads accept the technical names above or friendlier display names (e.g. Anonymized_PC_01, Transaction_Amount) — both work.

ℹ️ Technical details about this platform
  • Model: LightGBM_smote.pkl (best: PR-AUC 0.880) + scaler.pkl (RobustScaler fitted on training data only).
  • Preprocessing: Amount and Time are scaled with the same scaler and order used in training ([Amount, Time]), then the 30 features are ordered exactly as the model expects: V1..V28, Time_Scaled, Amount_Scaled.
  • Default threshold: 0.9944 (F1-optimal on the test set) — adjustable with the slider above.
  • Evaluation: when the file contains a Class column, verification metrics are shown (PR-AUC / ROC-AUC / Precision / Recall / F1 / Confusion Matrix).
  • Source: webapp/app.py (server) + deployment/predictor.py (inference) + deployment/schema.py (friendly names & glossary).
